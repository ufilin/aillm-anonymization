# Анонимизация датасета — домашнее задание (Нетология, «LLM в разработке»)

Кейс: компания «МегаКонсалт», отдел безопасности и аналитики. Нужно подготовить
датасет о продажах и дебиторской задолженности к внутреннему исследованию так,
чтобы из него нельзя было установить конкретного клиента или контактное лицо,
но чтобы аналитика осталась осмысленной.

## Результат

[`Анонимизированный_датасет.xlsx`](Анонимизированный_датасет.xlsx) — три листа:

| Лист | Что на нём |
|---|---|
| **Анонимизированный датасет** | 20 записей, 6 полей, готово к анализу |
| **Классификация полей** | каждое исходное поле: категория, метод, что сделано, влияние на анализ |
| **Отчёт и самопроверка** | шаги обработки, проверка k-анонимности, чек-лист, параметры |

## Что было в исходнике

20 записей, 9 полей: № п/п, название компании, город, ФИО контактного лица,
должность, телефон, номер договора, сумма договора, остаток дебиторской
задолженности.

## Что сделано

| Поле | Категория | Метод |
|---|---|---|
| № п/п | служебное | заменён на случайный `Клиент_ID`, строки перемешаны |
| Название компании | прямой идентификатор | псевдонимизация: `Клиент_001…020` |
| Город | квази-идентификатор | обобщение до федерального округа |
| ФИО, телефон | прямые идентификаторы (ПДн) | удаление |
| Должность | квази-идентификатор | удаление (характеризует контакт, а не клиента) |
| Номер договора | прямой идентификатор | псевдонимизация: `Договор_001…020` |
| Сумма, остаток долга | конфиденциальные атрибуты | шум ±5% + округление до 1 000 ₽ |
| — | производный показатель | доля непогашенной задолженности (формула) |

Ключевые решения:

- **Строки перемешаны**, иначе исходный порядок однозначно выдавал бы клиента.
- **Один коэффициент шума на запись** применяется и к сумме, и к остатку —
  абсолютные значения скрыты, а доля задолженности остаётся достоверной.
- **Должность удалена**, потому что в паре с регионом давала группы из одной
  записи, а для анализа на уровне компаний не нужна.
- **Ключ сопоставления** «компания → Клиент_ID» в файл не включён: он должен
  храниться отдельно и не публиковаться.

## Проверка

- Прямых идентификаторов в файле нет — проверено сквозным поиском по содержимому.
- k-анонимность по региону: **k = 2** (ПФО — 8 записей, ЦФО — 6, УФО — 4, СЗФО — 2).
- Структура и объём сохранены: 20 записей.
- Формулы без ошибок, значения пересчитаны.

Остаточный риск: набор маленький (20 записей), поэтому редкие сочетания
признаков теоретически сужают круг кандидатов. Снижено удалением прямых
идентификаторов, перемешиванием, случайными ID и шумом в суммах.

## Воспроизведение

`build.py` собирает файл из исходной таблицы (`Таблица_к_ДЗ.xlsx`):

```bash
pip install openpyxl
python build.py
```

Параметры в начале скрипта: `SEED = 20251125`, `NOISE = 0.05`, `ROUND_TO = 1000`,
маппинг городов на федеральные округа. Исходный файл в репозиторий не добавлен —
он содержит персональные данные.
